## Завдання 1: мінімальний елемент у 2D-масиві

Умова (варіант 3): знайти мінімальний елемент у двовимірному масиві,
значення якого вдвічі більше (≥ 2 × a[0][0]) першого згенерованого елемента.
Розмір масиву та діапазон значень задає користувач, значення генеруються
випадково. На екран виводиться згенерований масив (перші рядки/стовпці —
для великих масивів), результат пошуку і час виконання.

### Work Stealing (`ArrayMinFinderWorkStealing.java`)

Реалізовано через `ForkJoinPool` і `RecursiveTask`. Масив рядків рекурсивно
ділиться навпіл (`fork()`/`join()`), поки блок не стане меншим за поріг
(`THRESHOLD`). `ForkJoinPool` за замовчуванням дає кожному потоку власну
чергу задач (deque); коли потік звільняється, він «краде» задачі з кінця
черги іншого, ще завантаженого потоку. Це забезпечує автоматичне
вирівнювання навантаження навіть при нерівномірному розподілі роботи.

### Work Dealing (`ArrayMinFinderWorkDealing.java`)

Реалізовано через `ExecutorService` (`Executors.newFixedThreadPool`).
Головний потік («дилер») заздалегідь ділить рядки масиву на N рівних
блоків (N = кількість доступних процесорів) і роздає кожному потоку
свій блок через `submit()`. Подальшого перерозподілу немає — потік, що
закінчив свою роботу раніше за інших, просто чекає, поки завершать решта.

### Порівняння часу виконання

Обидві версії заміряють час програмно (`System.nanoTime()`). Орієнтовні
висновки (залежать від апаратного забезпечення, розміру масиву та
рівномірності розподілу «цікавих» елементів):

- На **рівномірно розподілених за обчислювальною складністю** задачах
  (як у цій задачі — усі елементи масиву обробляються за однаковий час)
  різниця між Work Stealing і Work Dealing зазвичай **невелика**, оскільки
  статичний поділ («dealing») уже дає збалансоване навантаження.
- Work Stealing дає перевагу, коли навантаження **нерівномірне**
  (наприклад, якщо частина підзадач виконується значно довше інших) —
  тоді вільні потоки одразу підхоплюють роботу перевантажених.
- Work Dealing має **менші накладні витрати** на диспетчеризацію (розподіл
  відбувається один раз), тоді як Fork/Join постійно створює нові об'єкти
  задач і виконує рекурсивне дроблення, що додає невеликий оверхед.
- На дуже великих масивах з великою кількістю рекурсивних поділів
  Fork/Join (Work Stealing) зазвичай масштабується краще завдяки кращому
  використанню всіх ядер процесора, особливо коли THRESHOLD підібраний
  вдало.

*(Заповніть цей розділ фактичними цифрами після запуску обох програм
на своєму комп'ютері з однаковими вхідними даними — це вимога завдання.)*

## Завдання 2: підрахунок символів у текстових файлах

Програма рекурсивно обходить вказану користувачем директорію, знаходить
файли текстового формату (розширення: txt, md, csv, log, java, json, xml,
html, css, js, properties, yml, yaml), читає їхній вміст і підраховує
кількість символів. У результаті виводиться ім'я кожного знайденого файлу
та кількість символів у ньому.

### Чому обрано Work Stealing (а не Work Dealing)

Структура файлової системи — це **дерево довільної форми**: заздалегідь
невідомо, скільки піддиректорій і файлів міститься на кожному рівні, і
робота може бути дуже нерівномірно розподілена (одна піддиректорія може
містити тисячі файлів, інша — жодного). Це саме той випадок, коли:

1. **Fork/Join Framework природно підходить** для рекурсивних деревоподібних
   структур — кожна піддиректорія стає окремою задачею (`RecursiveTask`),
   яка форкається в пул.
2. **Work Stealing ефективніший за Work Dealing** для такої задачі, тому що
   наперед неможливо (і невигідно) рівномірно "роздати" роботу потокам —
   обчислювальне навантаження стає відомим лише під час обходу дерева.
   Потоки, що обробили свою "легку" гілку дерева, одразу забирають задачі
   з черг потоків, які застрягли на "важких" піддиректоріях.

Тобто підхід обрано **не тому, що він простіший у реалізації** (обидва
підходи приблизно однакові за складністю коду), а тому, що він **краще
відповідає природі задачі** та дає кращу балансировку навантаження і,
відповідно, швидше виконання на нерівномірних файлових деревах.

## Як запустити

```bash
# Компіляція
javac task1/ArrayMinFinderWorkStealing.java -d out
javac task1/ArrayMinFinderWorkDealing.java -d out
javac task2/TextFileCharCounter.java -d out

# Запуск
java -cp out ArrayMinFinderWorkStealing
java -cp out ArrayMinFinderWorkDealing
java -cp out TextFileCharCounter
```

Кожна програма запитує потрібні дані в консолі (кількість рядків/стовпців,
діапазон значень або шлях до директорії) з перевіркою коректності введення.
